Решение для нас: используем как ориентир для классификации событий и зон поля в `MatchEvent` и `Text Commentary`, не перенося игровую математику в TypeScript.

## Принятые архитектурные решения

### Часть 1 (Блоки A и F)
- Разделение Rust-ядра на workspace (`src-rust/sim_core` + `src-rust/sim_wasm`).
- Потоковая изоляция в Web Worker, обмен данными через `Transferable ArrayBuffer` (без `SharedArrayBuffer` ради Android WebView), сохранение через мост `Worker → Main Thread → StorageAdapter` (IndexedDB / Capacitor SQLite).
- План разработки разбит на 10 последовательных этапов с обязательным зелёным CI.

### Часть 2 (Блок B: Модель данных Rust)
1. **Типизированные индексы (Newtype Handles)** вместо строковых ключей и указателей: `PersonId(u32)`, `PlayerId(u32)`, `ClubId(u32)`, `StaffId(u32)`, `CompId(u32)`, `ContractId(u32)`, `StringId(u32)`, `NationId(u16)`. Невалидный/отсутствующий индекс кодируется `u32::MAX` (`NONE_ID`), что экономит память по сравнению с `Option<u32>` в плотных массивах там, где важна компактность.
2. **Разделение Hot / Warm / Cold данных игрока**:
   - **SoA (`PlayerWorldSoA`)** для ежедневного обновления 18 000+ игроков: возраст, CA/PA, усталость/форма, статус травмы, контрактный статус, флаги развития хранятся в отдельных выровненных массивах.
   - **Компактные структуры атрибутов (`Attributes`, `HiddenAttributes`)**: 33 видимых атрибута (`u8` в диапазоне `1..=20`, с возможностью хранения дробного прогресса тренировок в отдельном `i8`/`u8` аккумуляторе развития `[0..100]` или `u16` fixed-point при росте, чтобы избежать скачков и потерь точности) и 9 скрытых параметров (`u8`).
   - **Cold-таблицы (`Person`, `PlayerCareerHistory`, `RetiredPlayer`)**: биография, строковые интернированные имена (`StringPool`), история сезонов хранятся отдельно и не попадают в кэш-линии дневных циклов.
3. **Матчевый движок в SoA + плоские буферы**:
   - `MatchPlayersSoA` для 22 активных игроков на поле (отдельные массивы `pos_x`, `pos_y`, `vel_x`, `vel_y`, `facing`, `stamina`, `intent`, `effective_attrs`) — максимизирует кэш-локальность и автовекторизацию в циклах 4 Гц.
   - `BallState` (позиция X/Y/Z, скорость X/Y/Z, спин X/Y/Z в `f32`) для 60 Гц подшагов физики.
   - `TickBuffer` с фиксированной схемой раскладки (`#[repr(C)]` заголовок + плоские секции `f32`/`u16`/`u8`) для передачи в JS без промежуточных аллокаций и сериализации JSON.
4. **Отказ от `#[repr(packed)]`**: все структуры используют естественное выравнивание Rust / `#[repr(C)]` (для ABI/буферов) с ручной сортировкой полей от большего размера к меньшему, чтобы исключить невыровненный доступ на ARM64 (Android) и WASM32.
